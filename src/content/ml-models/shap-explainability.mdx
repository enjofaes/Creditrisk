## The Explainability Problem

Regulators (ECB, FRB, PRA) require that credit decisions can be explained to applicants and auditors. SR 11-7 states models must be conceptually sound and outcomes interpretable. The EU AI Act adds to these requirements.

SHAP (SHapley Additive exPlanations) provides a mathematically grounded way to attribute a model prediction to individual features.

## Shapley Values: The Math

SHAP values are based on Shapley values from cooperative game theory. The SHAP value for feature $j$ is:

$$
\phi_j = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!(|F|-|S|-1)!}{|F|!} \left[f(S \cup \{j\}) - f(S)\right]
$$

In plain terms: the SHAP value is the **average marginal contribution** of feature $j$ across all possible orderings in which features enter the prediction.

**Key property**: SHAP values are **additive** — they sum exactly to the difference between the model output and the expected output:

$$
f(x) = E[f(x)] + \sum_j \phi_j
$$

## Global vs Local Explanations

SHAP supports both **global** and **local** interpretability:

| Type | Method | Use Case |
|---|---|---|
| Global | Mean absolute SHAP values | Feature selection, model documentation |
| Global | SHAP beeswarm plot | Distribution of feature impacts across portfolio |
| Local | SHAP waterfall/force plot | Individual loan decision explanation |
| Local | Dependency plots | Feature interaction analysis |

<Callout type="tip" title="For Regulatory Submissions">
Document both global feature importance (SHAP means) in your model documentation, and implement a system to generate individual SHAP explanations for credit decisions. The ECB Guide to Internal Models and DORA requirements increasingly expect this.
</Callout>
