## Why Gradient Boosting for Credit?

XGBoost and LightGBM consistently outperform logistic regression on discrimination metrics (Gini) for large tabular credit datasets. Key advantages:

- Handles non-linear relationships and interactions automatically
- Robust to outliers via tree structure
- Built-in handling of missing values
- Strong regularisation options (L1/L2)

The trade-off: **less interpretable** than logistic regression, requiring post-hoc explainability (SHAP) for regulatory use.

## Gradient Boosting in 60 Seconds

Gradient boosting builds an ensemble sequentially. Each new tree corrects the errors of the previous ensemble by fitting the **negative gradient** of the loss function:

$$
F_m(x) = F_{m-1}(x) + \eta \cdot h_m(x)
$$

Where $F_m$ is the $m$-th model, $\eta$ is the learning rate, and $h_m$ is a shallow tree fitted to residuals.

XGBoost adds second-order (Newton) gradients and explicit regularisation:

$$
\mathcal{L}^{(m)} = \sum_i \ell(y_i, \hat{y}_i^{(m-1)} + f_m(x_i)) + \Omega(f_m)
$$

$$
\Omega(f) = \gamma T + \frac{1}{2}\lambda \sum_{j=1}^T w_j^2
$$

## Class Imbalance in Credit Data

Default rates of 1–5% create severe class imbalance. Common approaches:

| Approach | Pros | Cons |
|---|---|---|
| `scale_pos_weight` | Simple, no resampling | Doesn't change training distribution |
| SMOTE oversampling | Generates synthetic minority examples | Can introduce noise |
| Threshold tuning | Preserves calibration | Doesn't affect model training |
| Class weighting | Standard, well understood | May reduce precision |

## Hyperparameter Sensitivity

Key XGBoost hyperparameters for credit risk:

| Parameter | Default | Credit Risk Guidance |
|---|---|---|
| `max_depth` | 6 | 3–5: shallower trees prevent overfitting on small samples |
| `learning_rate` | 0.3 | 0.01–0.1: smaller = more robust, needs more trees |
| `subsample` | 1.0 | 0.7–0.9: row subsampling adds regularisation |
| `scale_pos_weight` | 1 | Set to neg/pos ratio to handle imbalance |
| `min_child_weight` | 1 | Increase for sparse default events |
